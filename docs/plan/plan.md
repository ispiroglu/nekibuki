# Nekibuki Development Plan

## Overview
Nekibuki is a mobile application that enhances tourist experiences by providing instant, detailed explanations of attractions through photo recognition. Users take photos of tourist attractions, and the app identifies the subject using image recognition and delivers comprehensive information generated by Google Gemini Flash LLM.

**Tech Stack:**
- Frontend: React Native
- Backend: Go
- Database: PostgreSQL
- LLM Service: Google Gemini Flash
- Authentication: Google OAuth
- Hosting: VPS with Coolify
- Package Manager: npm
- API: REST

## Major Updates:

### **1. Technology Stack Changes:**
- **Removed external routing dependencies** (Gin, Gorilla Mux)
- **Updated to Go 1.22+** requirement for enhanced routing
- **Updated JWT package** to the maintained `github.com/golang-jwt/jwt/v5`

### **2. Enhanced HTTP Server Setup:**
- Added comprehensive HTTP server configuration using `net/http`
- Implemented middleware chain pattern for better modularity
- Added proper server timeouts and graceful configuration

### **3. Modern Routing Patterns:**
```go
mux.HandleFunc("GET /api/auth/google", handlers.GoogleOAuthRedirect)
mux.HandleFunc("POST /api/recognize/upload", middleware.AuthRequired(handlers.UploadAndRecognize))
mux.HandleFunc("GET /api/attractions/{id}", handlers.GetAttractionDetails)
```

### **4. Comprehensive Middleware Implementation:**
- **CORS middleware** for mobile client support
- **Logging middleware** with performance tracking
- **Rate limiting** using `golang.org/x/time/rate`
- **Authentication middleware** with JWT validation

### **5. Improved Project Structure:**
- Clear separation of route registration functions
- Better middleware organization
- Enhanced testing examples using standard library

## Key Benefits of This Approach:

✅ **Zero external routing dependencies** - reduces complexity and maintenance overhead
✅ **Better performance** - native Go optimizations without middleware layers
✅ **Enhanced pattern matching** - Go 1.22+ supports advanced URL patterns like `{id}` placeholders
✅ **Simpler deployment** - fewer dependencies to manage in production
✅ **Better testing** - easier to test with `httptest` package
✅ **Future-proof** - aligned with Go's direction and standard library improvements
